# 지역 CSV 준비 스크립트

한국 법정구역(시도 > 시군구 > 읍면동 > 리)을 Rails 지역 적재용 CSV(지역 CSV)로 바꾼다. 법정동코드에서 계층과 이름을, 법정구역정보에서 지도 범위(bbox)를 만든다. 이 폴더에는 스크립트와 테스트만 두고, **데이터 파일(법정동코드, 법정구역정보, 지역 CSV)은 커밋하지 않는다.**

## 원본 데이터

두 데이터는 법정동코드로 서로 이어 붙일 수 있다. 그러나 **생성 주기와 기준 시점이 달라서 데이터가 서로 어긋날 수 있다.** 어긋나면 [주의사항](#주의사항)을 따른다.

| 항목 | 법정동코드 | 법정구역정보 |
|---|---|---|
| 받는 곳 | [공공데이터포털](https://www.data.go.kr/data/15123287/fileData.do) | [브이월드](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=21) |
| 쓰는 정보 | 법정동코드, 법정동명 | 지도 범위(bbox) |
| 파일 형식 | CSV | SHP(zip). 시군구(SIG), 읍면동(EMD), 리(LIO) 세 파일 |
| 인코딩 | EUC-KR | cp949(`.dbf`) |
| 좌표계 | 해당 없음 | EPSG:5186 |
| 코드 칸 | `법정동코드` (10자리) | `A1` (시군구 5자리, 읍면동 8자리, 리 10자리) |
| 이름 칸 | `법정동명` | `A2` |
| 존재 여부 칸 | `폐지여부` (`존재`인 행만 쓴다) | 없음 |
| 기준일 정보 | 파일 이름의 날짜 | 파일 이름의 날짜 |
| 이용 조건 | 이용허락범위 제한 없음 | CC BY, 출처 표시 필요 |

`A1`, `A2`는 법정구역정보 `.dbf`의 칸 이름이다. 법정구역정보의 코드는 뒤에 0을 채워 10자리로 맞추면 법정동코드와 같아지고, 두 데이터를 이을 때는 이 코드만 쓴다. 이름은 표기가 달라서(`A2`는 시군구에서 시도 이름이 붙어 있다) 연결에 쓰지 않는다.

## 데이터 생성 순서

데이터 파일은 저장소 밖의 깨끗한 작업 디렉터리에서 다루고, 스크립트는 절대 경로로 실행한다.

1. **원본 받기**: [원본 데이터](#원본-데이터)의 두 데이터를 받는다. 법정구역정보는 zip이므로 시군구, 읍면동, 리를 각각 풀어 `.shp`를 꺼낸다.
2. **패키지 설치**: `pip install shapely pyproj pyshp`
3. **실행**
   ```
   python3 /절대경로/script/regions/build_kr_regions.py \
     --codes 법정동코드.csv --out kr_regions.csv \
     --sig 시군구.shp --emd 읍면동.shp --li 리.shp
   ```
   법정구역정보 세 파일을 **모두** 넘긴다. 빼면 오류 없이 그 레벨의 bbox가 비어 있는 지역 CSV가 나오고, [Rails 적재](#rails-적재)는 기존 행을 고치지 않아서 나중에 채울 수 없다. 스크립트는 파일 이름의 레이어 약어(SIG, EMD, LIO)를 보지 않으므로 각 파일을 `--sig`, `--emd`, `--li`에 맞게 넘긴다.
4. **요약 확인**: stderr 요약에 레벨별 행 수, bbox 자체·파생·없음 개수, 매칭 실패 코드 수가 나온다. 매칭 실패가 0이 아니면 [주의사항](#주의사항)을 따르고 3번부터 다시 한다.
5. **결과 확인**: 다음을 본다. 다르면 원인을 찾은 뒤 진행한다.
   - 지역 CSV의 행 수가 법정동코드의 `존재` 행 수와 같다.
   - 시도·시군구·읍면동은 bbox가 모두 있고, bbox가 없는 지역은 리뿐이다.
   - 레벨별 행 수와 bbox 개수가 [최신 지역 CSV](#최신-지역-csv)와 크게 다르지 않다. 형식은 [출력 CSV 계약](#출력-csv-계약)을 따른다.
6. **임시 DB로 적재 시험**: 임시 DB(`DATABASE_URL=sqlite3:<임시 경로>`)에 [Rails 적재](#rails-적재)를 해 본다. 추가 건수가 행 수와 같은지 본다.
7. **보관**: 지역 CSV를 팀 공유 드라이브에 올린다. 파일 이름에 기준월을 넣고, [최신 지역 CSV](#최신-지역-csv)의 값(원본 기준일 포함)을 이 지역 CSV의 값으로 바꾼다. 보관본: [Drive](https://drive.google.com/file/d/1OYVhFxnUhV-_bOI_49BP_Wh0kzhqJLZh/view?usp=drive_link)
8. **운영 적재**: [docs/deployment.md의 지역(Region) 도입 배포](../../docs/deployment.md#지역region-도입-배포-단계적).

스크립트 테스트: 저장소 루트에서 `python3 -m unittest discover -s script/regions -p "test_*.py"` (2번의 패키지 필요).

## 주의사항

### 1. 법정동코드와 법정구역정보의 코드가 어긋날 수 있다.
두 데이터는 기준 시점이 달라서, 한쪽에만 행정구역 개편이 반영된 시기가 있다. 코드가 한쪽에만 있으면 매칭에 실패하고, 그 지역은 자체 bbox를 받지 못한다. 스크립트는 실패한 코드를 **개수만** 보여 준다.

예: 2026-11에 지역 CSV를 처음 만들 때(법정동코드 20260929판, 법정구역정보 20261109판) 대구 달성군 구지면이 2026-09-30에 구지읍으로 바뀐 것이 법정구역정보에만 반영되어 있었다. 법정동코드의 구지면 `27710380xx` 16행이 법정구역정보에서는 구지읍 `27710268xx`여서 매칭 실패가 16개였다.

대처: 두 데이터는 법정동코드로 이어 붙일 수 있으므로, 어느 코드가 한쪽에만 있는지 찾고, **두 데이터의 기준일을 비교해 더 최신인 쪽을 기준으로 삼아** 오래된 쪽을 맞춘다. 오래된 쪽을 최신 판으로 다시 받을 수 있으면 다시 받아서 처음부터 한다. 다시 받을 수 없으면 오래된 쪽의 해당 행을 최신 쪽의 코드와 이름으로 바꾼다. 위 예에서는 법정동코드의 구지면 16행을 구지읍 코드와 이름으로 직접 바꿨다. 법정동코드는 CSV라서 직접 고칠 수 있지만, 법정구역정보를 고치는 방법은 아직 없다. 고친 뒤 다시 실행해 매칭 실패가 0인지 확인하고, 고친 행은 [최신 지역 CSV](#최신-지역-csv)의 "원본 보정" 항목에 적는다.

### 2. 잘못 적재하면 [Rails 적재](#rails-적재)로 고칠 수 없다. 
적재는 새 코드만 추가해서, bbox가 비었거나 코드·이름이 틀린 채 적재되면 고친 지역 CSV를 다시 적재해도 DB가 바뀌지 않는다(차이만 보고한다). 그래서 운영에 올리기 전에 [데이터 생성 순서](#데이터-생성-순서)의 4~6번을 모두 확인한다.

이미 적재했다면 지역을 지우고 다시 적재하지 말고, **틀린 값만 갱신한다.** 정류장이 가리키는 지역은 지울 수 없고, 지워도 정류장과의 연결이 끊어진다. 이 갱신 도구는 저장소에 없고, 운영 DB의 비어 있던 bbox를 채울 때 일회용 스크립트로 처리한 적이 있다. 절차는 이렇다.
1. 서버에서 백업한다([docs/deployment.md의 데이터와 백업](../../docs/deployment.md#데이터와-백업)).
2. 올바른 지역 CSV를 서버에 올린다.
3. 컨테이너 안에서 갱신 스크립트를 실행한다. 다음 안전장치를 둔다.
   - 코드로 행을 찾고 레벨과 이름이 지역 CSV와 같은지 확인한다. 다르거나 지역 CSV에 없는 코드가 있으면 아무것도 쓰지 않고 중단한다.
   - 고칠 칸이 비어 있는 행만 갱신한다. 이미 값이 있는 행은 건드리지 않는다.
   - 한 트랜잭션으로 처리하고, 먼저 롤백하는 시험 실행으로 갱신 건수를 확인한다.
4. 관리자 화면에서 결과를 확인한다.
5. 서버에 올린 지역 CSV와 스크립트는 지운다.
6. 공유 드라이브의 보관본이 틀린 값을 담고 있었다면 고친 지역 CSV로 바꿔 올린다([데이터 생성 순서](#데이터-생성-순서) 7번).

## 출력 CSV 계약

| 항목 | 규칙 |
|---|---|
| 인코딩 | UTF-8(BOM 없음) |
| 헤더 | `code,parent_code,level,kind,name,south,west,north,east` |
| 정렬 | 레벨 → 코드 순 |
| `level`, `kind` | 1 `시도`, 2 `시군구`(일반구 포함), 3 `읍면동`, 4 `리`. `kind`는 화면에 그대로 표시되는 한국어 이름이다 |
| `parent_code` | 코드로만 구한다. 시군구 → 시도(앞 2자리+0), 읍면동 → 앞 5자리+0(시군구 또는 일반구), 리 → 앞 8자리+00. 시도 행이 없는 시군구 자리 코드(세종 3611000000)는 최상위(레벨 1, `시도`)이고 읍면동이 바로 붙는다 |
| `name` | 전체 이름에서 상위 지역의 전체 이름을 뺀 값("수원시 장안구", "독도리"). 앞뒤 공백을 제거한다 |
| `south`, `west`, `north`, `east` (bbox) | 네 칸은 전부 비우거나 전부 채운다. 십진 도, 소수 6자리, 남≤북, 서≤동. 만드는 규칙은 아래 |

### bbox 만드는 규칙

위에서부터 차례로 적용한다.

1. **연결**: 법정구역정보 코드를 뒤로 0을 채워 10자리로 맞춰 법정동코드와 잇는다(5/8/10자리 모두 대응). 매칭 실패는 개수만 로그에 남는다.
2. **조각이 여럿이면**: 가장 큰 조각(원본 투영 좌표계 면적)의 bbox만 쓴다.
3. **도형이 없으면**: 깊은 레벨부터 하위 지역 bbox의 합집합을 쓴다(자식. 시 본체는 앞 4자리가 같은 일반구).
4. **그래도 없으면**: 비워 둔다. 지도는 상위 지역 bbox를 쓴다.

### 부모 bbox가 자식 bbox를 모두 덮지는 않는다

정류장 등록 화면은 지역을 고르면 지도를 그 지역의 bbox에 맞춘다. 본섬에서 멀리 떨어진 섬까지 bbox에 넣으면 범위가 바다로 넓어져서, 정류장이 실제로 있는 본섬이 지도에서 작게 보인다. 그래서 조각이 여럿인 지역은 가장 큰 조각만 쓴다(위 2번). 예를 들어 울릉군의 bbox는 독도를 뺀 본섬 범위(37.45~37.55, 130.79~130.92)다. 그 결과 떨어진 섬에 속한 자식 지역의 bbox가 부모 bbox 밖으로 나갈 수 있다. 오류가 아니라 이 규칙의 결과이고, bbox는 지도를 옮기는 데만 쓰며 정류장 좌표를 제한하지 않는다. 그 지역을 직접 고르면 자기 bbox로 지도가 이동한다.

## Rails 적재

```
bin/rails "regions:import[/경로/kr_regions.csv]"
```

새 코드만 추가하고(insert-only) 기존 코드는 고치지 않으며, 원본과 다른 필드는 차이로만 보고한다. 개발 DB를 건드리지 않으려면 `DATABASE_URL=sqlite3:<임시 경로>`로 임시 DB에서 먼저 확인한다.

## 최신 지역 CSV

공유 드라이브의 보관본([데이터 생성 순서](#데이터-생성-순서) 7번)이자 운영 DB에 적재된 지역 CSV의 내용이다. 다음에 새로 만들면 [데이터 생성 순서](#데이터-생성-순서) 5번에서 이 값과 비교하고, 보관본을 바꾸면 이 표도 새 값으로 바꾼다.

| 항목 | 값 |
|---|---|
| 원본 기준일 | 법정동코드 20260929판, 법정구역정보 `AL_D001_00_20261109` |
| 원본 보정 | 법정동코드의 구지면 `27710380xx` 16행을 구지읍 `27710268xx`로 수정([주의사항](#주의사항) 1번) |
| 행 수 | 총 20,560 = 시도 16(세종 포함) + 시군구 268 + 읍면동 5,067 + 리 15,209 |
| bbox | 자체 20,484 / 파생 29 / 없음 47(모두 리. 법정구역정보에 도형이 없다) |
| 매칭 실패 | 0 |
