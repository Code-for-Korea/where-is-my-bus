# 드라이버 앱 MVP 스펙

> 이 문서는 한동안 MVP 최초 정의 시점의 기준선(freeze)이었으나 **2026-10-24에 현행화**했다. 서버가 재작성되면서(Geofence 이벤트 기반, 차량에 노선 배정, 서버가 운행을 기준으로 관리) 앱의 동작이 이 문서와 달라졌기 때문이다. 지금은 **현재 구현을 설명하는 문서**이고, 설정값의 근거와 이력은 [`ISSUE.md`](ISSUE.md), 체크리스트는 [`README.md`](README.md)에 있다.

서비스명: **로컬버스 알리미 (Where is My BUS)**

위치 추적 로직은 [`traccar_client_sdk`](README.md#위치-송신-traccar-client-sdk)가 전부 처리한다. 이 앱이 만드는 것은 그 위에 얹는 UI와, **운행 시작·종료를 서버(Rails)에 알리는 일**이다. 위치(좌표)는 앱이 Traccar로 직접 보내고 우리 서버는 좌표를 받지 않는다.

## 동작 원칙

- **노선은 운전자가 고르지 않는다.** 관리자가 차량 한 대에 노선 하나를 배정해 두고, 앱은 그 노선으로 운행한다. 앱에는 노선 선택 화면이 없다.
- **서버가 기준이다.** 운행 시작은 서버 `trips/start`가 성공한 뒤에만 위치 전송을 켜고, 종료는 서버 `trips/end`가 성공한 뒤에만 멈춘다. 서버 요청이 실패하면 상태를 바꾸지 않고 안내한다.
- **앱을 껐다 켜도 이어진다.** 서버에 열린 운행이 있으면 앱이 위치 전송을 자동으로 다시 켠다.
- 서버 계약은 [`ISSUE.md`](ISSUE.md)의 `register`·`bus`·`trips start/end` 절이 기준이다.

## 오픈소스 멀티테넌트 전제

이 앱은 하나의 회사 전용이 아니라, 다른 지자체·버스운행사·국가가 각자 자기 서버(버스어드민+Traccar를 Docker로 패키징)에 띄워 그대로 가져다 쓸 수 있어야 한다. 그래서 **서버 주소를 앱에 고정할 수 없다** — 최초 1회 온보딩에서 입력받는다.

## 화면 구성

### 0. 스플래시
- 앱 로고/서비스명 표시. 3초 노출 후 저장된 온보딩 결과가 있으면 메인화면, 없으면 온보딩 화면으로. `tracker.init()`은 여기서 부르지 않음 — [ISSUE.md](ISSUE.md#trackerinit-호출-시점--지연-초기화최초-운행-시작-탭-때) 참고.
- 다른 화면과 동일하게 앱 전역 테마(시스템/라이트/다크 설정)를 따른다. 최초 실행 안내 팝업(프로젝트 소개 모달)도 마찬가지.

### 1. 온보딩(최초 실행 시 1회)
- **MVP는 수동 입력 한 화면**: `adminUrl`, `pin` 텍스트 필드 두 개를 **같은 화면에서 함께** 입력받는다. PIN만 먼저 받고 서버주소를 나중에(설정에서) 받는 2단계 흐름은 쓰지 않는다 — PIN 검증 자체가 서버주소 없이는 불가능하기 때문.
- "등록" 탭 → 앱이 그 `adminUrl`로 `POST /integrations/traccar/register`에 `pin` 전송 → 서버가 PIN으로 `Bus`를 조회해 `{ traccarServerUrl, deviceId, busNumber, licensePlate, route }` 응답. PIN은 **1회용**이라 한 번 등록에 성공하면 다시 쓸 수 없고(재발급은 관리자), 틀린 PIN을 5번 입력하면 같은 접속지에서 15분간 막힌다. 실패 시 같은 화면에서 에러 표시 후 재입력.
- 응답값(`traccarServerUrl`, `deviceId`, 차량 번호, 배정 노선 이름)을 로컬에 저장. `tracker.init(Config(...))` 호출은 여기서 하지 않고 메인화면의 최초 "운행 시작" 탭까지 미룸(아래 2번, [ISSUE.md](ISSUE.md#trackerinit-호출-시점--지연-초기화최초-운행-시작-탭-때) 참고).
- **QR 스캔은 후순위**(admin의 QR 생성 화면이 먼저 있어야 함, [ISSUE.md](ISSUE.md#미구현-구현-필요) 참고) — 나오면 이 화면에 스캔 버튼만 추가, 스캔 결과로 같은 두 필드를 채워주는 방식.

### 2. 메인화면
- **차량·노선 표시** (상단) — 차량 번호와 **관리자가 배정한 노선 이름**. 노선이 배정되지 않았으면 경고 배너를 보여 주고 운행을 시작할 수 없다.
- **운행 시작/종료 버튼** (화면 중앙, 크게) — 탭하면 운행을 시작/종료한다. 전송 중/중지 상태를 색상·아이콘으로 즉시 구분.
  - 시작: ① 서버 `trips/start` 호출(노선은 보내지 않음) → 성공하면 ② **최초 1회** `tracker.init(Config(serverUrl, deviceId))` 후 `tracker.start()`. GPS 센서 구독이 `init()` 시점부터 시작되는 SDK 특성상, 운전자가 버튼을 누르기 전까지 센서가 켜지지 않게 하려는 의도([ISSUE.md](ISSUE.md#trackerinit-호출-시점--지연-초기화최초-운행-시작-탭-때) 참고). ②가 실패하면(위치 권한 거부 등) 서버 운행을 되돌린다.
  - 종료: 서버 `trips/end` 호출 → 성공하면 `tracker.stop()`. 서버 호출이 실패하면 "운행 중" 상태를 유지하고 다시 누르면 재시도한다.
  - 노선 미배정(`422 no_route_assigned`)·알 수 없는 기기(`404`)·네트워크 실패는 SnackBar로 안내한다.
- **서버가 보는 위치** (운행 중에만) — 서버가 방문 기록으로 계산한 **이전 · 현재 · 다음 정류장** 이름. 방금 정류장을 떠났으면 현재 칸에 "이동 중"이 보인다. 화면이 열릴 때·앱이 앞으로 돌아올 때·운행 중 10초마다 서버(`GET /integrations/traccar/bus`)에서 새로 받는다. 응답이 없으면 마지막 값을 유지한다. ETA(몇 분 뒤 도착)는 없다.
- **자동 재개** — 화면이 열릴 때 서버에 열린 운행이 있는데 앱이 운행 중이 아니면(앱을 껐다 켬) 위치 전송을 자동으로 켠다. 서버의 운행이 이미 끝났는데 앱이 운행 중이면 위치 전송을 멈추고 안내한다.
- **지속추적 안내문** (하단, 고정 문구) — "앱을 나가도 위치 전송이 지속됩니다. 단, 원활한 버스위치 정보 전송을 위해서는 기기를 전원에 연결하고, 운행중에는 앱 화면을 켜두시길 권장합니다." 지속추적 자체는 세션마다 결정할 값이 아니라(꺼지면 곧 서비스 목적이 무력화됨) 토글은 설정화면으로 옮기고, 메인엔 동작 설명 + 운영 팁만 노출. **단, 보장이 아니라 최선노력** — OS가 강제 종료하면 중단될 수 있음. [ISSUE.md](ISSUE.md#지속추적-문구--최선노력이지-보장이-아님) 참고.
- **설정 버튼** (우측 상단) — 설정화면으로 이동.

### 3. 설정화면
- **기기 식별자 정보** — `deviceId`(= `traccar_unique_id`) **읽기전용 표시**. 값 자체를 직접 입력하지 않고, 바꾸려면 "재등록" 버튼으로 온보딩 화면(0번)을 다시 띄움. 설정화면 자체는 서버 최초 입력 경로가 아님.
- **서버 URL 정보** — `adminUrl`/`traccarServerUrl` **읽기전용 표시**(같은 이유로 재등록을 통해서만 변경).
- **상태보기** — 현재 추적 상태, 마지막 전송 시각, 배정 노선, 지속추적 설정, 운행 시작/정지 이력을 보여 주는 화면으로 이동.
- **'지속추적' 토글** — 꺼짐: 앱이 포그라운드일 때만 전송. 켜짐(**기본값**): 백그라운드에서도 전송 시도(Android 포그라운드 서비스 알림 상주, iOS 백그라운드 모드). 세션마다 결정할 값이 아니라 메인이 아닌 여기 상주 — 끄면 위치 전송 자체가 앱을 나가는 순간 끊기므로 기본은 켜짐, 상시 화면 고정 등 특수 운용에서만 끔.
- **언어** — 한국어/English 전환. 기본은 시스템 언어 자동 감지(`PlatformDispatcher.instance.locale`), 지원 목록 밖 언어는 English로 폴백. 명시적으로 고르면 그 값을 재실행 후에도 유지.
- 위치 정확도/거리는 서버(Traccar)가 아니라 SDK 로컬 설정이라 운전자가 조정할 대상이 아님 → UI 없이 [고정값](#위치-추적-고정값)으로 박는다. Advanced settings, 로컬 비밀번호 잠금도 MVP에 없음 — 사유는 [ISSUE.md](ISSUE.md) 참고.

### 4. 상태보기 화면
- 설정화면의 "상태보기" 진입점으로 여는 별도 화면(또는 하단 시트).
- 현재 추적 상태, 마지막 전송 시각, 배정 노선, 지속추적 켜짐/꺼짐, 운행 시작/정지 이력 리스트. (좌표는 보여 주지 않는다 — 앱은 좌표를 서버에 보내지 않고 Traccar로만 보낸다.)

## 위치 추적 고정값

Traccar 서버엔 표시/설정되지 않는 SDK 로컬 파라미터라 UI로 노출하지 않고 앱 코드(`lib/tracking_controller.dart`)에 상수로 고정한다. 정류장 도착·출발을 **Traccar가 위치로 정류장 영역(30m 정사각형)의 출입을 판단**해서 기록하므로, 버스가 영역을 지나는 동안 위치가 최소 한 번은 찍히도록 SDK 기본값보다 촘촘하게 정했다. 변경 이력(2026-10-24)은 [ISSUE.md](ISSUE.md#위치-전송-설정-변경-2026-10-24)에, 시뮬레이터 측정은 [`위치 전송 빈도 시험`](../docs/location-sampling-test.md)에 있다:

| 필드 | SDK 기본값 | 고정값 | 이유 |
|---|---|---|---|
| `accuracy` | MEDIUM | **HIGH** | MEDIUM(WiFi/셀타워)은 도로 위 정밀도 부족(진행바 튐). HIGHEST는 정밀도 이득 대비 배터리 소모만 큼 |
| `distanceMeters` | 75 | **15** | 30m 폭 정류장 영역을 지날 때 위치가 2~4번 찍히도록. 30m 간격이면 영역 경계·도로 위치에 따라 놓칠 수 있다 |
| `intervalSeconds` | 300 | **10** | 느리게 움직이거나 정차 중에도 10초 안에 최신 위치가 간다 |
| `heartbeatIntervalSeconds` | 0 | **30** | 멈춰 있어도 30초 안에는 위치를 보낸다(백그라운드 포함) |
| `angleDegrees` | 0 | **0(비활성 유지)** | 버스 추적엔 방향 변화 트리거 불필요 |
| `stopDetection` | true | **false(끔)** | 켜면 iOS에서 모션(피트니스) 권한이 추가로 필요해짐 — 위치 앱이 피트니스 데이터를 요구하는 데서 오는 불신 리스크가, 장시간 정차 시 GPS 배터리 절약보다 크다고 판단. [ISSUE.md](ISSUE.md#설정--advanced-settings-공식-앱-기준-5개-bufferwakelockstopdetectionpreferplatformproviderspassword) 참고 |
