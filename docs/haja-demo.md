# 하자센터 시연 데이터 (서울 영등포구)

시골·도서 지역이 아닌 **도시 안에서** 서비스를 보여 주기 위한 시연 시드다. 하자센터(서울특별시 영등포구, 37.5251401, 126.9032761) 주변 1.5km 안의 정류장 5개로 단방향 순환 노선을 만들고, 시뮬레이터로 버스 한 대를 운행시킨다. 기존 고성 데모(`docs/local-demo.md`)와 같은 구조(Rails ↔ Traccar Geofence 이벤트)를 쓰므로 이 문서는 그 문서의 시연 절차를 아는 사람 기준으로 **데이터가 다른 부분만** 적는다.

## 정류장 좌표의 출처

정류장 좌표는 **OpenStreetMap(OSM) 노드**에서 가져왔다. 서울 열린데이터광장의 버스정류소 OpenAPI는 발급 키가 있어야 전수 조회할 수 있어(샘플 키는 1~5행만 허용) 쓰지 않았다. 그래서 이 좌표는 **서울시 공식 데이터가 아니다.** 각 좌표는 아래 OSM 노드 주소로 누구나 다시 확인할 수 있다.

| 정류장 | 위도 | 경도 | OSM 노드 |
|---|---|---|---|
| 영동초교 | 37.5252508 | 126.9068323 | https://www.openstreetmap.org/node/12512226846 |
| 신화병원 | 37.5244724 | 126.9053251 | https://www.openstreetmap.org/node/12534076733 |
| 영등포시장 | 37.5215029 | 126.9049984 | https://www.openstreetmap.org/node/12534076765 |
| 영등포역 | 37.5168407 | 126.9074712 | https://www.openstreetmap.org/node/357951991 |
| 영등포구청 | 37.5253315 | 126.8964059 | https://www.openstreetmap.org/node/357894954 |

정류장 Geofence는 30m 정사각형이라 서로 겹치면 안 된다. 영등포역 주변은 정류장이 촘촘해서(같은 정류장의 상행·하행 노드가 13~46m 차이) **한 정류장당 노드 하나만** 골랐고, 인접 정류장 사이는 최소 159m다.

## 시드가 만드는 것

| 항목 | 값 |
|---|---|
| 노선 | 하자센터 시연 노선 (단방향 순환: 영동초교 → 신화병원 → 영등포시장 → 영등포역 → 영등포구청) |
| 차량 | 서울70사1001 (하자01) |
| 정류장 | 위 표의 5개, 영등포구 지역에 속함 |

정류장·노선·차량은 관리자 화면과 같은 등록 서비스(`StopRegistration` 등)를 거치므로 **Traccar에도 Geofence·그룹·기기가 함께 만들어진다.** 차량 PIN(6자리)과 `deviceId`(hex 12자)는 자동 생성되고 시드 마지막에 출력된다.

## 사전 준비: 영등포구 지역 적재

시드는 지역을 만들지 않는다. 이미 적재된 영등포구(지역 코드 `1156000000`)를 찾아 쓰고, 없으면 아래 메시지로 실패한다.

```
지역 코드 1156000000(서울특별시 영등포구)를 찾을 수 없습니다. 먼저 bin/rails "regions:import[CSV 경로]"로 지역을 적재하세요.
```

지역 CSV는 `script/regions/build_kr_regions.py`로 만든다(사용법은 `script/regions/README.md`). 데이터 파일은 커밋하지 않는다.

```bash
bin/rails "regions:import[/경로/kr_regions.csv]"
```

## 로컬에서 실행

Traccar가 떠 있어야 한다. `bin/dev`는 Traccar 컨테이너를 함께 띄우고 `TRACCAR_*` 환경변수를 채우므로 그대로 쓸 수 있다. `docker compose`로 띄웠다면 아래 명령의 `bin/rails`를 `docker compose exec rails bin/rails`로 바꿔 실행한다.

```bash
bin/dev                            # Rails + Tailwind watch + 로컬 Traccar 컨테이너
bin/rails demo:seed_haja_center    # 시연 데이터 (여러 번 실행해도 안전하다)
bin/rails "demo:drive[하자01]"     # 시뮬레이터 (번호판 "서울70사1001"로도 된다)
```

- 승객 화면 http://localhost:3000 에서 영동초교 등의 정류장을 고르고 "하자센터 시연 노선"을 연다.
- `demo:drive`는 Rails(localhost:3000)와 Traccar(localhost:5055)가 모두 떠 있어야 한다. 시뮬레이터는 기본 **약 45km/h**로 움직이고(`BusSimulator`의 `speed_kmh: 45`, 전송 간격 1초 기준이며 간격을 늘리면 표시 속도만 그만큼 낮아진다), 정류장마다 6초 정차한다. 시연 시간을 줄이려면 `demo:drive[하자01,1,2]`처럼 정차 시간을 줄인다.
- 시드 출력의 PIN과 `deviceId`는 운전자 앱 등록에 쓸 수 있다(로컬 시험 방법은 `docs/local-demo.md` "운전자 앱 로컬 시험").

## 시연 때 계속 도는 버스 (자동 루프)

승객 화면의 "약 N분 후 도착"은 구간마다 **끝난 운행 3번 이상**의 방문 기록이 쌓여야 나온다(`SegmentTimes`, `MIN_SAMPLES = 3`). 3번 미만이면 "N정거장 전"만 보인다(표본이 부족할 때의 표시 방식은 팀 회의에서 아직 정하지 않았다). 그래서 시연 전에 시뮬레이터를 여러 바퀴 돌려 표본을 먼저 쌓고, 시연 중에는 계속 돌린다.

```bash
# 준비: 4바퀴를 돌려 구간 표본을 쌓는다 (정차 15초, 지나간 뒤 15초 대기, 바퀴 사이 20초)
bin/rails "demo:drive[하자01,2,15,4,15,20]"
# 시연: 중단할 때까지 계속 (Ctrl+C로 끝내면 열린 운행도 종료한다)
bin/rails "demo:drive[하자01,2,15,0,15,20]"
```

인자는 `버스,전송간격초,정차초,반복횟수,지나간뒤대기초,바퀴사이대기초` 순서다. 반복횟수 0은 계속 돈다.

- **간격은 준비 때와 시연 때 같게 한다.** 간격 1초(약 12.5m씩)로는 구간이 60초 안에 끝나 "곧 도착"만 나온다. 2~3초 이상으로 늘려야 "약 N분"이 보이고, 구간 시간 통계도 같은 간격으로 쌓여야 맞다. (위 예시는 로컬용 2초이고, 서버 시연 당일은 5초로 고정한다.)
- **통계 캐시가 10분 유지된다.** 준비 바퀴를 마친 뒤 10분을 기다리거나 서버에서 캐시를 지운다: `bin/rails runner 'Rails.cache.delete("segment_times/6")'`(6은 노선 ID, 관리자 노선 화면 주소의 번호).
- **화면 갱신은 5초마다다.** 목표 정류장에서 "도착했습니다"가 보이도록 정차를 15초 이상으로, 마지막 정류장을 지난 뒤 "지나갔습니다"가 보이도록 지나간 뒤 대기를 15초 이상으로 둔다. 바퀴 사이(운행이 없는 동안)에는 "운행 중인 버스가 없습니다"가 보인다.
- **서버 노선에 붙이려면** 환경변수로 주소를 바꾼다: `DEMO_RAILS_URL`(Rails)과 `TRACCAR_OSMAND_URL`(Traccar 위치 수신 5055). 대상 버스는 그 노선에 배정된 차량의 번호판이나 번호다. 시뮬레이터 운행은 운영 DB에 방문 기록으로 남고 그 노선의 ETA 통계가 시뮬레이션 값으로 채워지므로, 시연 전용 노선에서만 쓴다.

### 시연 당일 시뮬레이터 실행 방법 (운영 서버 차량)

노트북에서 실행한다(서버에서 돌리지 않는다). 노트북의 로컬 DB에는 운영 차량이 없으므로 `DEMO_DEVICE_ID` 환경변수로 deviceId를 직접 준다. deviceId는 사실상 비밀번호라 인자로 주면 셸 기록과 `ps`에 남으므로 `read -s`로 입력해 환경변수로만 전달한다. 값은 관리자 화면에서 확인하고 문서·채팅·셸 기록에 남기지 않는다.

1. 운영 차량 하자버스101이 준비돼 있는지 확인한다(아래 "시연 차량 만들기", 노선 6 배정, 준비 운행 완료).
2. 시연 전 확인: 열린 운행이 없다, 구간 중앙값 4개 모두 표본이 3 이상이다, 41→40 구간 중앙값이 60초를 넘어야 "약 N분"이 보인다(이번 준비 운행 기준 약 121초). 캐시는 위 "통계 캐시" 항목을 따른다.
3. 실행한다.

```bash
read -s DEMO_DEVICE_ID; export DEMO_DEVICE_ID
DEMO_RAILS_URL=https://where-is-my-bus.codefor.kr TRACCAR_OSMAND_URL=http://where-is-my-bus.codefor.kr:5055 \
  bin/rails "demo:drive[하자버스101,5,15,0,5,2]"
unset DEMO_DEVICE_ID
```

- 인자는 `버스,전송간격초,정차초,반복횟수,지나간뒤대기초,바퀴사이대기초`다. 전송 간격 5초는 준비 운행과 같아야 한다. 반복 0은 계속 돈다. Ctrl+C로 중단하면 열린 운행도 닫힌다.
- `DEMO_DEVICE_ID`가 있으면 첫 인자(번호판)는 로그용일 뿐 조회에 쓰이지 않는다.

**시작 정류장 옵션(하자센터 1정거장 전부터 출발)**: 7번째 인자로 정류장 **이름**을 주면 **첫 바퀴만** 그 정류장부터 종점까지 달리고(그 정류장 100m 앞에서 출발하며 접근 구간 동작은 그대로다), **2번째 바퀴부터는 전체 노선**(44→43→41→40→42)을 정상 운행한다. 버스는 항상 전체 노선을 운행하고, 이 옵션은 시작 위치만 정한다. 반복횟수 1이면 지정 정류장부터 종점까지 한 번만 달리고 끝난다. 인자는 `버스,전송간격초,정차초,반복횟수,지나간뒤대기초,바퀴사이대기초,시작정류장이름` 순이다. 노선 6에서 하이서울유스호스텔(40)의 한 정거장 전인 영등포구민회관.영등포경찰서(41)에서 시작하려면 다음과 같이 한다. 첫 바퀴는 구민회관에서 시작해 종점까지 가고, 다음 바퀴부터 전체 노선을 계속 돈다.

```bash
bin/rails "demo:drive[하자버스101,5,15,0,5,2,영등포구민회관.영등포경찰서]"
```

- 효과(첫 바퀴에만): 첫 바퀴가 41 → 40 → 42 세 정류장으로 짧아져 하자센터 1정거장 전부터 곧바로 보인다. 이 바퀴에는 앞 두 정류장(44 당중초등학교, 43 당산동삼익아파트)의 방문 기록이 없어 그 화면에는 운행이 보이지 않는다. 2번째 바퀴부터는 44부터 전체 노선이라 모든 정류장에 방문 기록이 남는다. 로그에는 `== 2번째 운행 (전체 노선)`으로 표시된다.
- 이름은 정확히 같아야 하고(노선에 없으면 정류장 목록과 함께 오류), 노선의 마지막 정류장(종점)은 지정할 수 없다. 노선 응답에 정류장 id가 없어 id 지정은 지원하지 않는다. 이름에 쉼표가 있으면 rake 인자 구분과 충돌해 쓸 수 없다(이 정류장 이름은 쉼표가 없다).
- 간격은 준비 운행과 같게 5초로 둔다.
- ETA 표본은 구간(41→40, 40→42)별로 쌓이므로 기존 운행의 표본을 그대로 쓴다. 새 준비 운행은 필수가 아니다(앞서 구간 중앙값은 41→40 약 121초, 40→42 약 75초).
- 공백(접근 100m, 약 40초)은 이 옵션으로 줄지 않는다. 첫 바퀴가 짧아질 뿐 바퀴 사이 대기와 접근 구간은 그대로이고, 2번째 바퀴부터는 위 공백 설명이 그대로 적용된다(바퀴 사이 공백 약 40초).
- 3정류장 iframe 데모 페이지(`public/demo-haja.html`)와 함께 쓰기 좋다.
- 이 코드는 아직 서버에 배포되지 않았고 노트북에서만 실행한다.

**기대 화면 순서와 공백**: 출발 직후 "약 N분 후 도착" → "도착했습니다" → "지나갔습니다" 순으로 보인다. 그런데 운행 사이에 "운행 중인 버스가 없습니다"/"위치 확인 중"이 보이는 **공백이 약 40초** 생긴다. 접근 구간 100m를 12.5m(전송 한 번의 이동 거리)로 나눈 횟수에 전송 간격을 곱한 시간에 바퀴 사이 대기가 더해진 값이다. **이번 시연에서는 이 공백을 줄이지 않기로 했고** 시뮬레이터 코드도 바꾸지 않았다. 줄이려면 PR 본문의 방안 A~F를 참고한다(접근 거리 옵션 등, 미결).

**시연 차량(하자버스101) 만들기**: 백업(`./backup-storage`, `bin/backup-traccar`)을 먼저 하고, 서버에서 `BusRegistration`으로 차량을 만들어 노선 6에 배정한다(관리자 화면의 차량 등록과 같은 경로다). deviceId와 PIN은 관리자 화면에서만 확인한다.

**시연 뒤 정리 순서** (서버 `bin/rails runner`, 그 차량 기준):

1. 그 차량의 `stop_visits` 삭제
2. 그 차량의 `trips` 삭제 (방문 기록이 먼저여야 한다)
3. `BusRegistration.destroy`로 차량과 Traccar 장치 삭제
4. `Rails.cache.delete("segment_times/6")`로 ETA 통계 캐시 삭제

## 데모 화면 (iframe 3정류장)

하자센터 앞뒤 3개 정류장의 승객 화면을 한 화면에 나란히 보여 주는 정적 페이지다.

- 파일: `public/demo-haja.html` (인라인 CSS만 쓰는 단독 HTML)
- 주소: `https://where-is-my-bus.codefor.kr/demo-haja.html` (**배포 뒤에만 열린다**)
- 구성: 정류장 41(영등포구민회관.영등포경찰서, 직전), 40(하이서울유스호스텔, 내 정류장), 42(신화요양병원, 다음·종점)의 노선 6 화면 3개가 동시에 갱신된다.
- 같은 출처 서버에서만 동작한다. 노트북의 로컬 파일(`file://`)로 열면 iframe이 `X-Frame-Options: SAMEORIGIN`에 막힌다.
- 수정한 뒤에는 정적 파일 캐시가 1년이라 시연 브라우저에서 강제 새로고침(Cmd+Shift+R)하거나 주소 뒤에 `?v=2`를 붙인다.
- 배포 뒤 확인: `curl -sI https://where-is-my-bus.codefor.kr/demo-haja.html`로 200과 `cache-control`을 본다.
- 한계: iframe마다 헤더가 중복된다. 자세히보기 모달은 그 iframe 안에서만 열린다. GA4 이벤트가 iframe마다 전송되어 통계에 섞인다. 정류장 id는 운영 서버 기준이라 로컬 개발 DB와 다를 수 있다.

## 서버 시연 사전 점검

시연 링크(QR)가 가리키는 노선을 관리자 화면에서 직접 만들었다면(예: 노선 6 "하자센터", 정류장 하이서울유스호스텔) **`demo:seed_haja_center`는 운영에 돌리지 않는다.** 시드는 이름이 다른 별도 노선("하자센터 시연 노선")을 새로 만들 뿐이다. 아래는 그 노선 기준이다. 노선 ID와 번호판은 환경에 맞게 바꾼다.

**1. 데이터 (관리자 화면)**

- [ ] 노선의 정류장 순서가 시연 동선과 맞는다. 시연 정류장이 종점이 아니면 "지나갔습니다"는 그 정류장을 떠난 뒤 다음 정류장으로 가는 동안 보인다.
- [ ] 정류장 좌표를 확인한다. 지오펜스가 30m 정사각형이라 정류장끼리 30m 이상 떨어져 있어야 하고, 시연 장소(하자센터는 영등포구 영신로 200, 하이서울유스호스텔도 같은 도로명 주소)에 가까워야 한다.
- [ ] 모든 정류장에 지역이 있다(영등포구는 코드 `1156000000`, 운영에 적재돼 있다). 확인: `bin/kamal app exec --reuse 'bin/rails runner "p Stop.where(region_id: nil).count"'`가 0.
- [ ] 정류장마다 Traccar 지오펜스가 있고 노선 그룹에 연결됐다. 일부만 실패했다면 관리자의 `sync_geofence`/`sync_group`으로 복구한다.

**2. 차량**

- [ ] 그 노선에 시연 전용 차량을 배정한다. 기존 시험 차량은 다른 노선에 쓰고 있을 수 있고, 노선은 운행 중에 바꿀 수 없다.
- [ ] 번호판(또는 번호)을 `demo:drive`의 인자로 쓴다. deviceId와 PIN은 비밀값이므로 채팅·문서에 붙이지 않는다.

**3. 서버 상태**

- [ ] 배포된 버전이 최신 `main`이다(ETA·도착 예상 아이콘 포함). 서버의 컨테이너 이미지 태그로 확인한다.
- [ ] Traccar가 떠 있고 위치 수신 포트(5055)가 열려 있다. 5055는 임시 평문이다(`docs/deployment.md` "첫 배포의 위치 수신은 임시로 평문").
- [ ] Traccar가 Rails로 지오펜스 이벤트를 전달한다(`X-Ingest-Token`). 시뮬레이터로 한 바퀴 돌려 정류장 방문 기록이 생기는지 본다.
- [ ] 시연 전에 백업한다(`./backup-storage`).

**4. ETA 표본 (가장 오래 걸린다)**

- [ ] 위 "시연 때 계속 도는 버스"의 준비 운행으로 구간 표본을 쌓는다(4바퀴 이상). 서버 노선에 붙이는 환경변수와 실행 방법은 "시연 당일 시뮬레이터 실행 방법"을 따른다. 반복 옵션은 이 브랜치(또는 병합 뒤 `main`)에만 있으므로 시연 PC가 그 코드로 실행한다.
- [ ] 통계 캐시 10분을 기다리거나 `Rails.cache.delete("segment_times/노선ID")`를 실행한다.
- [ ] 준비 때와 시연 때 전송 간격을 같게 한다.
- [ ] 소요 시간은 정류장 사이 거리에 달렸다. 한 바퀴를 돌려 보고 바퀴 수와 대기 시간을 정한다.

**5. 시연 직전 리허설**

- [ ] 시연 링크를 휴대폰으로 열어 본다(QR을 찍어서).
- [ ] 출발 → "약 N분 후 도착" → "도착했습니다" → "지나갔습니다"가 차례로 보이는지 확인한다.
- [ ] 시연 중에는 반복 횟수 0으로 계속 돌린다. 바퀴 사이에는 "운행 중인 버스가 없습니다"가 보이므로 바퀴 사이 대기를 짧게(20초 이하) 둔다.

**6. 시연 후 정리**

- [ ] 시뮬레이터 운행은 운영 DB에 방문 기록으로 남고 그 노선의 ETA 통계를 시뮬레이션 값으로 채운다. 시연 전용 노선이면 그대로 둘지, 실운행 전에 정리할지 정한다.
- [ ] `bin/pull-server-data`로 받은 `tmp/production-*`에는 비밀번호 해시·deviceId·PIN이 있으므로 쓴 뒤 지운다.

## 서버에 적재

운영에는 시드가 없고, `demo:seed`는 운영에서 abort하지만 **`demo:seed_haja_center`는 운영에서도 실행할 수 있다.** 데이터를 넣는 작업이므로 백업을 먼저 한다. 시연 노선을 이미 관리자 화면에서 만들었다면 이 시드는 필요 없다(위 "서버 시연 사전 점검").

```bash
# 1. 백업 (서버에서. 절차는 docs/deployment.md "데이터와 백업")
./backup-storage

# 2. 시연 데이터 적재 (배포 PC에서)
bin/kamal app exec --reuse "bin/rails demo:seed_haja_center"

# 3. 확인: 지역 없는 정류장이 0이어야 한다
bin/kamal app exec --reuse 'bin/rails runner "Stop.where(region_id: nil).count"'

# 4. 운행 시뮬레이션은 서버에서 하지 않는다. 운전자 앱으로 등록·운행하거나,
#    로컬에서 서버를 가리켜 돌리려면 DEMO_RAILS_URL과 TRACCAR_OSMAND_URL을 지정한다.
```

서버에도 영등포구 지역이 먼저 적재돼 있어야 한다. 지역 적재는 `docs/deployment.md` "지역(Region) 도입 배포"의 절차(CSV를 서버로 올려 컨테이너 안에서 `regions:import`)를 따른다.

## 고성 데모와의 차이

| | `demo:seed` (고성) | `demo:seed_haja_center` |
|---|---|---|
| 운영자 계정 | 만든다 (`operator@example.com`) | 만들지 않는다 |
| 지역 | 만들지 않는다 | 만들지 않고, **이미 적재된 영등포구를 찾아 쓴다** (없으면 실패) |
| 운영 실행 | abort | 실행할 수 있다 |
| 정류장·노선·차량 | 6개·2개·2대 | 5개·1개·1대 |

## 문제 해결

- **"Traccar 연결을 기다리는 중..."이 반복되다가 실패한다**: 등록 서비스는 Traccar 호출과 한 트랜잭션이라 Traccar가 내려가 있으면 Rails 변경도 취소된다. 시드는 약 30회(2초 간격) 재시도하다가 포기한다. Traccar를 띄운 뒤(`bin/traccar status`로 확인, `bin/dev`를 다시 띄우거나 `bin/traccar up`) **같은 명령을 다시 실행한다.** 시드는 여러 번 실행해도 안전하다(이미 있는 것은 건너뛴다).
- **`demo:drive`가 "버스를 찾을 수 없습니다"**: 시드를 먼저 실행하지 않았거나 다른 DB를 보고 있다. `bin/rails demo:seed_haja_center`를 실행한다.
- **승객 화면이 "위치 확인 중"에서 안 넘어간다**: `docs/local-demo.md` "문제 해결"과 같은 원인(Traccar → Rails 이벤트 포워딩)이다.
- **"이미 있는 정류장 ... 시연 정류장과 다릅니다"로 시드가 중단된다**: 같은 이름의 다른 정류장(위치 50m 초과 또는 다른 지역)이 이미 있다는 뜻이다. 시연 노선에 잘못 붙지 않도록 일부러 멈춘다. 그 정류장이 시연용이 맞다면 위치·지역을 고치고, 아니면 이름을 바꾼 뒤 다시 실행한다.
- **재시도 중 Traccar에만 남은 자원(orphan)이 생길 수 있다**: 시드가 Traccar 오류로 재시도하는 동안 Traccar 쪽에만 group·geofence·device가 만들어질 수 있다(`AGENTS.md` 알려진 함정 3번과 같은 한계). 복구는 관리자 화면의 `sync_group`/`sync_geofence`/`sync_device`로 한다.
- **지역 오류로 시드가 실패한다**: 위 "사전 준비"의 `regions:import`를 먼저 한다.
