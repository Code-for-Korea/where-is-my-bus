# 지역(Region) 개념 복원 설계

작성일 2026-11-11. 브레인스토밍 결과이며 구현 전 설계다. 구현 계획은 이 문서를 승인한 뒤 따로 쓴다.

## 1. 목적과 배경

관리자가 정류장 좌표를 지도에서 정할 때, OSM은 전 세계 지도라서 원하는 곳(예: 경상북도 울릉군)까지 줌인·드래그로 찾아가기 번거롭다. 지역을 고르면 지도가 그 범위로 좁혀지게 한다.

팀 의견 수렴 결과(전제):

- 다중 지역 지원이 필요하다. 인접 지역과 이어진 노선이 있을 수 있다.
- 지역 개념 복원은 필요하다. 다만 **정류장 등록에 지역 제한은 없다.** 운영자가 A 지역을 설정해도 다른 지역의 정류장을 등록할 수 있다.
- MVP는 한국 기준이고, 추후 한국 밖에서도 쓸 수 있어야 한다. 한 번에 한 나라 안에서만 서비스한다는 전제를 둔다.

## 2. 확정한 결정

| 주제 | 결정 |
|---|---|
| 지역의 범위 | 시도·시군구(일반구 포함)·읍면동·리를 모두 "지역"으로 본다. |
| 데이터 모델 | 자기참조 `regions` 테이블 하나. 부모는 부모 지역 참조로 둔다. |
| 국가 | 단일 국가 전제. `country` 행과 코드 체계 열을 두지 않는다. |
| 정류장 ↔ 지역 | 정류장은 지역에 필수로 속한다(어느 레벨이든). 최소 깊이는 **레벨 ≥ 2**(시도 + 시군구)이고 설정값으로 둔다. |
| 노선 ↔ 지역 | 저장하지 않는다. 노선의 지역은 소속 정류장의 지역에서 조회 때 파생한다. 정류장이 없는 노선은 "지역 미정". 도로만 지나는 중간 지역은 목록에 나타나지 않는다(승객이 이용할 수 없으므로 의도한 동작). |
| 운영자 기본 지역 | **두지 않는다**(구현 후 제거). 대신 새 정류장 폼이 가장 최근에 등록한 정류장의 지역을 미리 채운다(`Stop.last_registered_region`). 설정 저장 없이 연속 등록의 반복 선택을 줄인다. |
| 경계 | MVP에서 다각형을 저장하지 않는다. 지역마다 bbox(남, 서, 북, 동)만 둔다. |
| 이식성 | SQLite 기준이지만 DB 엔진이 바뀔 수 있어(`docs/tech-stack-debate-result.md`) PostGIS·ltree 같은 확장에 기대지 않는다. |
| 삭제 | 정류장이나 자식 지역이 있으면 삭제할 수 없다. 폐지된 지역은 비활성화한다. |
| 재적재 | **새 코드만 추가하고 기존 행은 건드리지 않는다.** 원본과 다른 행은 결과 보고로 알린다(수동 수정 보호가 목적). |

## 3. 데이터 모델

### regions

| 컬럼 | 설명 |
|---|---|
| code | 외부 데이터와 이어주는 키. 유일. 한국은 법정동코드 10자리. |
| parent_id | 부모 지역. 최상위는 비어 있다. |
| level | 종류의 고정 위계 번호. 시도 1, 시군구 2, 읍면동 3, 리 4. 일반구도 시군구(2)이다. |
| kind | 레벨 종류 이름(시도, 시군구, 읍면동, 리 등. 화면에 그대로 표시한다). level과 한 쌍이다. |
| name | 표시 이름. 상위 레벨의 이름은 빼되, 일반구는 소속 시를 붙인다("수원시 장안구"). 일반구가 시도 아래에서 시와 나란히 놓이므로 이름만으로 구별돼야 한다. |
| south, west, north, east | bbox. 비어 있을 수 있다(nullable). |
| active | 비활성화 표시. |

규칙:

- `부모.level < 자식.level`. 1 차이일 필요는 없다.
  - 세종특별자치시(레벨 1)는 시군구 없이 읍면동(레벨 3)을 바로 자식으로 둔다.
  - **일반구는 시와 나란한 시군구**이다. 부모는 시도이고, 일반구 아래에 읍면동이 있다(수원시 자체에는 읍면동 자식이 없다). 법정동코드 원천 사이트의 시군구 드롭다운이 시와 일반구를 한 목록에 나란히 보여 주는 구조와 같다.
  - 트레이드오프: 시 아래에 구가 포함되는 관계(`수원시 ⊃ 장안구`)는 부모 참조로 표현하지 않는다. "수원시 전체 정류장" 같은 조회가 필요해지면 코드 앞 4자리로 묶는다.
- 최소 깊이 규칙은 `level ≥ 2`로 정의되므로 세종은 읍면동을 고르면 통과한다.
- bbox가 없는 지역은 지도가 가장 가까운 상위 지역의 bbox를 쓴다.

### 다른 테이블

- `stops.region_id`: 최종적으로 NOT NULL. 아래 "운영 마이그레이션" 참고.

## 4. 데이터 적재(한국)

데이터는 저장소에 넣지 않는다. 국가마다 적재 도구를 따로 둔다.

**역할 분담**

- **계층·이름·코드**: 국토교통부 법정동코드 CSV(`폐지여부=존재`만 사용). 2026-09-29 기준 파일에서 직접 확인한 내용:
  - 코드는 모두 10자리이고 유일하다. 구조는 시도(2)·시군구(3)·읍면동(3)·리(2)이다. 존재 행 20,560개.
  - 부모는 코드로 구한다(레벨 판별 후 한 단계 위 코드). 이름으로 부모를 찾으면 안 된다(일반구 이름 끝 공백 등으로 실패한다).
  - 시도 행도 이 CSV에 있다. 세종특별자치시는 시도 행이 따로 없고 시군구 자리의 코드(3611000000)가 최상위다.
  - 일반구는 시군구로 취급한다. 부모는 시도이다(시와 같은 부모). 읍면동의 부모는 시가 아니라 구이다. 이름은 법정동명에서 시도를 뺀 값("수원시 장안구")이다.
- **경계(bbox)**: VWorld 법정구역정보(SHP, EPSG:5186, CC BY). 시군구·읍면동·리 레이어만 있고 시도 레이어는 없다.

**준비 스크립트(Python, shapely/pyproj) → CSV → Rails 로더**

- 스크립트는 좌표계를 위경도로 변환하고, bbox는 **가장 큰 덩어리** 기준으로 계산한다(섬 지역 보호). 도형이 없는 지역은 하위 지역 bbox를 합친다(시도는 자식, 구 단위 도형만 있는 시는 코드 앞 4자리가 같은 구들. 부모 참조가 아니라 코드로 묶는다).
- Rails 로더는 CSV(코드, 부모 코드, 레벨, 레벨 종류, 이름, bbox)만 안다. 나라가 바뀌어도 로더는 그대로다.
- 재적재는 새 코드만 추가한다. 이름이 바뀌는 등 원본과 달라진 행은 "추가 N / 변경 없음 N / 원본과 다름 N(코드, DB 값, 원본 값)"으로 보고한다.
- 출처 표시(CC BY)를 앱 어딘가에 넣는다.

## 5. 관리 화면

### 지역 CRUD(새 "지역" 페이지)

- 수만 행이라 평면 목록이 아니라 부모를 골라 자식을 보는 트리 탐색과 검색을 둔다.
- 생성·수정·비활성화·삭제(제한 조건 있음). 코드 수정은 재적재 매칭을 깨므로 경고하거나 막는다.
- bbox는 지역 폼의 지도에서 원하는 범위에 맞춘 뒤 "현재 지도 범위를 영역으로 저장" 버튼으로 입력한다(구현됨. 숫자 직접 입력 아님).
- 수동 생성이 가능하므로 법정동 데이터가 없는 나라에서도 쓸 수 있다.

### 정류장 폼

- 연쇄 선택(시도 → 시군구 → …)으로 지역을 고른다. 하위 지역은 "선택한 지역의 자식 목록"을 JSON으로 주는 관리자 엔드포인트(또는 Turbo Frame)로 가져온다.
- 지역을 고르면 지도가 그 지역 bbox로 맞춰진다(`fitBounds`).
- 정류장 등록 시 지역 제한은 없다. 어느 지역이든 고를 수 있다.

### 지도 시작 위치

기존: 입력 좌표 → 정류장 평균 → 브라우저 위치 → 고정 위치(고성). 변경:

입력 좌표 → 선택한 지역 bbox(새 폼은 최근 등록 지역이 미리 선택됨) → 브라우저 위치 → 나라/세계 보기

`Stop.center`와 `Stop::MAP_FALLBACK_CENTER`는 제거한다.

## 6. 운영 마이그레이션(단계적)

운영 데이터는 테스트 데이터라 수정해도 된다. 다만 정류장은 방문 기록이 있으면 삭제할 수 없고(UI 삭제 제한), 삭제하면 Traccar에 geofence가 남으므로 지우지 않고 지역을 채운다.

1. 배포 1: `regions` 테이블과 `stops.region_id`(nullable), 관련 화면.
2. 서버에서 지역 적재 실행.
3. 기존 정류장의 지역을 채운다(백필).
4. 배포 2: `stops.region_id`를 NOT NULL로 바꾸고 폼에서 필수화.

## 7. 범위 밖

- 지역 경계 다각형 저장과 점-다각형 판정.
- 좌표로 지역을 자동 제안하는 역지오코딩(`docs/future-improvements.md` 36번).
- 정류장 대량 등록(35번).
- 여러 나라를 한 인스턴스에서 서비스하는 것(코드 체계 열, 국가 행).
- 주소 검색(지오코딩).

## 8. 구현 때 확인할 것

1. VWorld SHP의 8자리 코드가 법정동코드 앞 8자리에 대응하는지(미확인. SHP 샘플로 검증). 리 레이어 코드 길이도 확인한다.
2. SHP 속성의 한글 인코딩(CP949 여부).
3. 일반구가 있는 시의 도형이 시 단위로도 있는지, 구 단위만 있는지.
4. ~~재적재 이력을 DB에 남길지~~ **결정(구현 중)**: 남기지 않는다. 로더가 실행 결과(추가·변경 없음·원본과 다름)를 보고할 뿐이다.
5. ~~레벨↔이름 저장 방식~~ **결정(구현 중)**: `regions`의 `level`과 `kind` 두 컬럼으로 둔다(참조 표 없음).
6. ~~비활성(폐지) 지역에 속한 정류장의 처리~~ **결정(구현 중)**: 정류장은 그대로 둔다. 새로 지역을 고르는 폼 선택지에서만 비활성 지역을 제외하되, 이미 그 지역에 속한 정류장의 편집 폼에는 "(비활성)"으로 표시한다.

1~3은 2026-11-11에 실제 SHP로 확인했다(결과: `script/regions/README.md` "검증 상태"). 코드는 SIG 5자리·EMD 8자리·LIO 10자리이고 법정동코드 앞자리와 대응한다. 인코딩은 cp949이다. 일반구는 구 단위 도형만 있어 시 본체 bbox는 구들에서 파생한다.
